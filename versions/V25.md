# SOCDOF Version 25 Changelog

All notable changes and technical implementation details for SOCDOF Version 25.x are documented here in English.

## Version 25.2.21 — Update Download Time Estimate

- `src/components/UpdatePromptModal.tsx`: the remaining time was `(100 - progress) * 0.4` seconds, which ignored the real speed. It now derives the speed from progress samples (exponential moving average, weight 0.2 on the newest sample) and computes `remainingMb / speedMb`. The first two seconds show `updates.time_calculating` instead of an estimate.
- `src/lib/i18n.ts`: added `updates.time_calculating` in de, en, fr and es.
- `electron/main.cjs`: the update launcher's PowerShell `error` handler now opens the installer with `shell.openPath` when PowerShell cannot start, so the update is not lost.

## Version 25.2.20 — Installer Language and Install Folder

- `electron-builder.json`: `nsis.installerLanguages` now lists only `de_DE`, `en_US`, `fr_FR` and `es_ES`, so the language selector no longer shows all bundled NSIS languages. The default is detected from the OS locale.
- `electron-builder.json`: `nsis.allowToChangeInstallationDirectory` is `false`, so the directory page is skipped and the installer uses its fixed default location. Users can no longer type a different parent folder.
- `scripts/generate_sleek_installer_assets.cjs`: the sidebar status block now centres its three text lines (`gravity North`, offsets `+0`) instead of left-aligning them at `+12`. The committed BMP files are not regenerated in this change; run the script with ImageMagick to apply it.

## Version 25.2.19 — Startup and Password Recovery Fixes

- `electron/main.cjs`: the PowerShell launchers for the update installer and the updating splash had no `error` listener. A missing `powershell.exe` raised `spawn powershell.exe ENOENT` and crashed the main process. Both now log the error instead.
- `src/components/AuthGate.tsx`: the recovery screen only checked the legacy `user.recovery` field, so accounts with questions in `user.recoveries` were blocked. It now accepts either source, matching the verification in `resetPasswordWithRecovery`.

## Version 25.2.18 — Localized User Management Badges

- The account-type badge in `UserManagementSettings.tsx` used string concatenation (`${labels.personal}es Konto`), which produced wrong words outside German. It now uses the new keys `users.account_personal_badge` and `users.account_business_badge`.
- The auto-login hint used a hard-coded German word ("öffnen"). It now uses `users.open_tab`.
- Keys were added in en, de, fr and es in `src/lib/i18n.ts`.
- Roles tab restyled: the role list, role settings, app permissions and user assignment are separate sections. The selected role uses the accent color (`var(--accent-light)`, `var(--accent)`), each app is a bordered checkbox with an enabled-count badge, and the assignment block has its own heading.
- Create dialog: the frame, progress bar, icon and buttons use the accent variables (`--accent`, `--accent-ring`) instead of hard-coded indigo. Next/Create is the primary action; Back is a secondary button.
- New keys in en, de, fr and es: `users.role_list`, `users.role_editor`, `users.role_apps_hint`, `users.role_assign_hint`, `users.role_select_hint`, `users.role_count`.
- Reviewed the settings overlays. The system-reset modal (`SettingsModule.tsx`) and the monitor identify overlay (`DisplaySettingsSection.tsx`) are intentional full-screen layers and were left unchanged.
- Verified: `npm run lint` and `npm run build` green. Not verified in a browser.

## Version 25.2.17 — Temporary Password Feedback for New Users

- The temporary password step in `UserManagementSettings.tsx` now shows the same strength bar as first-time setup. `computePasswordStrength` in `AuthGate.tsx` is exported and reused, so the rules stay identical.
- A password under 8 characters shows a red hint under the field once Create was attempted.
- Create checks the username and display name on step 1 and the password on step 2, and jumps to the step with the missing field. The field is framed in red with the existing `requiredFieldClass` styling.
- Verified: `npm run lint` and `npm run build` green. Not verified in a browser.

## Version 25.2.16 — Recovery Screen Follows Dark Mode

- Root cause: the saved `theme_mode` lives only in IndexedDB (`company_profile`). `App.tsx` applied it only after the async company load, so the login, recovery and other `AuthShell` screens rendered with the default light palette until then, even when Dark Mode was saved.
- Fix: the mode is cached in localStorage under `socdof_theme_mode` (written in `applyThemeMode`, read by `readCachedThemeMode`). It seeds the initial `company` state and is applied in the first theme effect, before the IndexedDB load. Behaviour after login is unchanged.
- `AuthShell` in `AuthGate.tsx` keeps its normal `dark:` classes and no longer forces the dark class; a previous change that forced it has been reverted.
- Verified in headless Chromium through the real UI: an account was created in Erstsetup with Dark and with Light, then "Passwort vergessen" was measured. Dark: `html.dark`, body `rgb(2, 6, 23)`, card dark, white title. Light: no `dark` class, body `rgb(246, 248, 251)`, card near-white, dark title. No page errors.

## Version 25.2.14 — Password Recovery Blank Screen Fixed

- Root cause: `LoginScreen` in `AuthGate.tsx` returned `<RecoveryScreen />` (`if (recover)`) before calling the hooks `useState` (`isQuitConfirmOpen`) and the `isSigningIn` early return came before the `isQuitConfirmOpen` hook as well. Opening "Passwort vergessen" changed the number of hooks, React threw "Rendered fewer hooks than expected", and the whole app unmounted, which showed a blank screen. All hooks are now declared before the early returns.
- Accounts without a recovery question show `recoveryUnavailable` directly in `RecoveryScreen`.
- Verified in headless Chromium at 1280x800 and 390x844: the recovery form renders, there are no page errors and no horizontal overflow.

## Version 25.2.13 — Password Recovery and Layout Fixes

- `RecoveryScreen` in `AuthGate.tsx` lists the text of all recovery questions (`user.recoveries`, falling back to `user.recovery`) instead of only the first one. `resetPasswordWithRecovery` already accepts an answer to any of them.
- The admin add-user form in `UserManager` (`AuthGate.tsx`) uses `grid-cols-2` on small screens and `sm:grid-cols-5` from the `sm` breakpoint, so the inputs no longer get squeezed on narrow windows.
- Checked by reading the code only: the auth shell (`AuthShell`) scrolls and centers at all sizes. No browser test was possible in this environment.

## Version 25.2.12 — Power Menu Overlay

- The power menu (`desktop.start_power`) in `DesktopWindowWorkspace.tsx` is an absolutely positioned overlay (`absolute bottom-full`) above the start menu footer. The footer container is `relative`, so opening the menu no longer shifts the start menu content.

## Version 25.2.11 — Window Control Cooldown Corrected

- Closing an in-app window locks the SOCDOF app window controls (minimize, fullscreen, close) for 2 seconds. Minimize and maximize of in-app windows are not locked.

## Version 25.2.10 — User Management Tab Wrapping

- The user-management tab bar in `UserManagementSettings.tsx` uses `flex-wrap` instead of horizontal scrolling, so the last tab is no longer clipped on narrow windows.

## Version 25.2.9 — In-App Window Control Cooldown

- The minimize, maximize and close buttons of in-app windows (`DesktopWindowWorkspace.tsx`) now share the existing 3-second controls cooldown. A click starts the lock and further clicks on these buttons are ignored until it ends.

## Version 25.2.8 — User Management Tab Layout

- The four tabs of the user management (profile, accounts, roles, security) used a two-column grid on small screens, so long labels overlapped. They now sit in a horizontally scrollable row with their natural width.

## Version 25.2.7 — First Administrator Login Fix

- The first administrator set the password during setup but was still flagged as "must change password" (`mustChangePassword`, set by `createUser` as `!passwordless`). Login showed the "Neues Passwort festlegen" screen.
- `createUser` now sets the flag only for accounts the administrator adds (`!passwordless && users.length > 0`).
- `parseUsers` clears the legacy flag of the first administrator once, tracked by `legacyFirstAdminFixed`, so later administrator resets still work.

## Version 25.2.6 — Account Creation and First Login

- New accounts show "Temporäres Passwort" (temporary password) and no security question during creation.
- Required fields show a red asterisk and a red border when empty; no error text is shown.
- At the first login, the user sets their own password and one or more security questions (preset or own).

## Version 25.2.1 — Portable First-Run Progress Splash
- **First-Run Progress Splash (`electron/main.cjs`, `electron/splash.html`, `electron/preload.cjs`)**:
  - The splash now shows a localized progress bar (de, en, fr, es) while the data folder is prepared, but only on the first launch of a data folder.
  - Progress steps are pushed from the main process over `socdof:splash-progress`.
  - A marker file `first-run-setup-complete.flag` in the user data folder (the portable `data` folder when portable) records a finished setup. Later launches skip the splash and the setup progress.

## Version 25.2.0 — Custom Roles, Passwordless Accounts & Per-Person Recovery
- **Per-User Language (`src/components/DesktopWindowWorkspace.tsx`)**:
  - Choosing a language in the language dialog now stores it on the signed-in account (`preferences.language`) instead of the shared company profile, so it is not synchronized across users.
- **Custom Roles & App Permissions (`src/lib/auth.ts`, `src/components/UserManagementSettings.tsx`)**:
  - Administrators can create, rename and delete custom roles in the new "Roles & Apps" tab of User Management.
  - Each role has a list of allowed app modules; administrators tick the apps per role.
  - Each non-admin user can be assigned one role (or none, which means full access). Admins always keep full access.
  - Roles are stored in the security settings (`customRoles`); users reference them via `roleId`. Existing accounts are unchanged.
  - Enforced centrally via `canUserAccessModule()` when opening a window (`src/components/DesktopWindowWorkspace.tsx`) and in the command palette (`src/components/CommandPaletteModal.tsx`).
- **Passwordless Accounts for Non-Admins (`src/lib/auth.ts`, `src/components/AuthGate.tsx`)**:
  - Non-admin accounts may be created without a password (`passwordless`). The login card shows a "<Name> continue" button and signs in directly.
  - Administrators always require a password.
- **Per-Person Security Question (`src/lib/auth.ts`, `src/components/AuthGate.tsx`)**:
  - The security question is asked on first sign-in per person (`recoveryPending`) or only once for all users, depending on the setting.
- **Admin View Cleanup (`src/components/UserManagementSettings.tsx`)**:
  - The "Current password" and "Temporary reset" fields are hidden when an administrator edits their own account.
- **Localization (`src/lib/i18n.ts`)**: All new role and passwordless texts are translated in German, English, French and Spanish.
